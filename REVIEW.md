# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health()` / line 72-74 | Returns 200 OK unconditionally; doesn't verify MongoDB connectivity. Contract requires 200 only if MongoDB answers a ping, else 503. | Call `/health` when MongoDB is down → returns 200 instead of 503. | Add `client.admin.command("ping")` in try/except; return 503 on failure. |
| 2 | `compute_late_minutes()` / line 33-37 | Doesn't truncate seconds from `punch_in` before calculation (R1: "Instants are truncated to whole seconds before any calculation"). Doesn't handle overnight shifts (R1: punch-in earlier than shift_end belongs to previous day's shift). | Punch-in at 09:40:01 → should give 10 late minutes (floor), but seconds not truncated. Overnight shift 22:00-06:00, punch-in at 05:00 → date should be previous day, late calc wrong. | Truncate `punch_in` to seconds first. For overnight shifts, determine correct shift date per R1 before computing late. |
| 3 | `compute_work_hours()` / line 40-41 | Uses Python `round()` which is banker's rounding (round half to even). R4 requires "rounded to 2 decimals half-up". | Work hours 9.125 → Python round gives 9.12, half-up should give 9.13. | Implement half-up rounding: `math.floor(x * 100 + 0.5) / 100`. |
| 4 | `compute_overtime()` / line 44-47 | (a) Doesn't handle overnight shifts: shift_end <= shift_start means shift ends NEXT calendar day. (b) Missing 30-minute minimum threshold (R3: "counted only if that is at least 30; otherwise 0"). (c) Doesn't truncate seconds from `punch_out` before calculation (R1). (d) Uses `int()` truncation which is floor for positive but not explicit. | Overnight shift 22:00-06:00, punch-out 06:40 → overtime should be 40 min but calculates negative. Punch-out 18:35 (shift 18:30) → 5 min overtime, should be 0 (under 30 min threshold). | Add overnight shift logic: if shift_end <= shift_start, end datetime is date+1 day. Apply floor minutes, then `max(0, minutes)` only if minutes >= 30 else 0. Truncate seconds first. |
| 5 | `EmployeeIn` model / line 53-60 | No validation: `emp_code` pattern (`^EMP\d{4,6}$`), email format, `shift_start` != `shift_end`, shift time format HH:MM, `joined_on` date format. | POST `/employees` with `emp_code="abc"`, `shift_start="09:30"`, `shift_end="09:30"` → accepts invalid data. | Add Pydantic validators: `field_validator` for pattern, email regex, shift inequality, time format. |
| 6 | `PunchInIn` model / line 63-66 | No validation: `punched_at` must be epoch milliseconds (int, >= 100000000000, <= 4102444800000), not seconds/float/string. `status` must be PRESENT/WFH/ON_DUTY only (not ABSENT/LEAVE). | POST `/attendance/punch-in` with `punched_at=1234567890` (seconds) or `status="ABSENT"` → accepts invalid input (422 expected). | Add validators for `punched_at` range and `status` enum. |
| 7 | `create_employee()` / line 77-85 | (a) Race condition: check-then-insert not atomic; concurrent creates can both pass check and insert duplicates. (b) `created_at` uses `datetime.now()` naive local time; should be UTC BSON datetime (epoch ms in API). (c) No unique index on `emp_code` created at startup. (d) Returns `created_at` as datetime object, not epoch milliseconds. (e) No validation of shift_start != shift_end, emp_code pattern, etc. | Two parallel POST `/employees` with same `emp_code` → both may return 201. `created_at` in response is ISO string not epoch ms. | Create unique index on `emp_code` at startup. Use `insert_one` with try/except DuplicateKeyError → 409. Store `created_at` as `datetime.now(timezone.utc)`. Convert to epoch ms in response. |
| 8 | `list_employees()` / line 88-96 | (a) `skip = page * page_size` off-by-one: page 1 should skip 0, not page_size. (b) `total = count_documents({})` ignores department filter. (c) No sort by `emp_code` ascending (contract requires it). (d) No `page_size` max 100 validation. (e) Returns `created_at` as datetime not epoch ms. | Page 1 with page_size=20 → skips first 20 items. Filter by department → total shows all employees. | Fix skip to `(page-1)*page_size`. Count with filter `q`. Add `.sort("emp_code", 1)`. Validate `page_size <= 100`. Convert `created_at` to epoch ms. |
| 9 | `punch_in()` / line 99-121 | (a) `datetime.fromtimestamp(punched_at/1000)` creates naive local-time datetime, not IST/UTC. (b) `ts.date()` uses local date, not IST date (R1: date is IST calendar date of punch_in). (c) Race condition: check-then-insert for duplicate (emp_code, date). (d) No 404 for unknown employee. (e) No validation of `status` enum (PRESENT/WFH/ON_DUTY only). (f) No validation of `punched_at` epoch milliseconds range. (g) Overnight shift date handling wrong (R1). (h) `compute_late_minutes` called with untruncated seconds. (i) Returns `id` field (MongoDB _id) which shouldn't exist in API response. (j) Returns `punch_in` as datetime not epoch ms. | Parallel punch-ins same emp_code/date → both may succeed. Unknown emp_code → 500/AttributeError. punched_at in seconds → accepted. Response has extra `id` field. | Use unique index on (emp_code, date) + try/except DuplicateKeyError→409. Check employee exists→404. Validate status & punched_at. Convert punched_at to UTC datetime, derive IST date properly. Handle overnight shift date per R1. Truncate seconds. Remove `id` from response. Convert punch_in to epoch ms in response. |
| 10 | `list_attendance()` / line 124-150 | (a) Loads ALL matching docs into memory (`list(find(q))`), sorts in Python → OOM at 100k docs. (b) Sort only by date desc, missing secondary `emp_code` asc. (c) `total = len(docs)` after full load; should use `count_documents(q)`. (d) No validation `date_from` <= `date_to` (422 expected). (e) No `page_size` max 100 validation. (f) Returns `id` field (MongoDB _id). (g) Returns `punch_in`/`punch_out` as datetime not epoch ms. (h) No index to support query. | Large dataset → slow/out of memory. date_from > date_to → returns empty instead of 422. Response has extra `id`. | Use MongoDB `.sort([("date", -1), ("emp_code", 1)]).skip().limit()`. Use `count_documents(q)` for total. Validate date_from <= date_to. Validate page_size. Remove `id`. Convert datetime fields to epoch ms. Create supporting indexes. |
| 11 | General / startup | No indexes created at startup. Contract: "Create all indexes at startup, idempotently." Grader seeds DB with only `_id` index. | All queries do COLLSCAN; explain endpoint will fail IXSCAN check. | Add startup event handler creating: unique `emp_code` on employees, unique `(emp_code, date)` on attendance_logs, compound indexes for list/analytics queries. |
| 12 | General / datetime handling | No consistent conversion between API (epoch milliseconds int) and MongoDB (BSON datetime UTC). PyMongo returns naive datetimes by default. | All endpoints return datetime objects instead of epoch ms integers. Timezone confusion in calculations. | Use `tz_aware=True` in MongoClient. Store all instants as UTC BSON datetime. Helper: `ms_to_dt(ms)` → `datetime.fromtimestamp(ms/1000, tz=timezone.utc)`. Helper: `dt_to_ms(dt)` → `int(dt.timestamp() * 1000)`. Apply at API boundaries. |
| 13 | General / response serialization | FastAPI returns datetime objects as ISO strings, but contract requires epoch milliseconds integers for all instants. | Any endpoint returning `punch_in`, `punch_out`, `created_at`, history times → wrong format. | Custom JSON encoder or Pydantic model with serialization to epoch ms. Or convert manually in each endpoint before return. |
| 14 | `create_employee` / line 82 | `doc["created_at"] = datetime.now()` — naive datetime, no timezone. Should be UTC. | created_at stored as local time, not UTC. | Use `datetime.now(timezone.utc)`. |
